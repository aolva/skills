# Aolva Identity Ops

Aolva SaaS 体系的共享身份基建是 **Clerk** + `login.lumwe.com` 登录中心
(见 `Platform/Docs` 身份相关对齐文档)。本技能规范 agent 处理身份域任务的方式。

## 适用判定

- **用户体系/登录/注册/会话/权限**:按本技能流程走。
- **修改身份配置(域名/登录方式/路由)**:先读平台对齐文档,改动前列出影响面并请用户确认。
- **生产数据**:只读操作直接执行;写操作(改用户、发邀请、改权限)需用户确认。

## 工作流

1. **定位**:先确认目标产品接的是共享登录中心还是独立身份(查 `login.lumwe.com` hub 归属);不同产品可能走不同租户。
2. **读配置**:从代码/配置(环境变量、Clerk 仪表盘只读信息)确认当前登录方式、回调地址、权限模型。
3. **实现/修改**:
   - 新增页面/接口的鉴权:统一走登录态 + 权限校验,不重复造轮子;
   - 环境差异(dev/staging/prod 的 Clerk 实例)在改动中显式区分;
   - 回调地址/域名白名单改动列出"哪些环境、哪些产品受影响"。
4. **验证**:本地/沙箱验证登录闭环(登录→回调→会话→登出);权限变更验证越权场景(低权限账号访问高权限资源被拒)。
5. **交付**:说明改动点 + 验证结果 + 未覆盖场景。

## 规则

- **不硬编码密钥**:Clerk API key/JWT secret 一律走环境变量/密钥管理。
- **不绕过鉴权**:调试期间也不在代码里写"临时跳过登录"的路径;需要时用白名单环境变量并标注 TODO。
- **用户数据安全**:不把用户邮箱/ID 打印进日志或贴进无关输出;会话令牌永不落盘。
- **权限模型变更**:涉及角色/权限结构变化时,先给迁移影响清单(存量用户/现有接口)再动手。
