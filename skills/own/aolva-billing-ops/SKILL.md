# Aolva Billing Ops

计费是平台共享能力:订阅/用量计费贯穿各 SaaS 产品,算力集散路由(NewAPI 底座)
另有**按 token/算力用量计费**口径。本技能规范计费域任务,重点是**口径一致、账实相符**。

## 适用判定

- 订阅/套餐/价格配置、订单与支付、退款、账单核对 → 本技能。
- 价格变更、计费规则变更 → 必须输出影响面(存量订阅/已生成账单/退款政策)并请用户确认后执行。

## 工作流

1. **定口径**:先确认计费模式(固定订阅?用量计费?混合?)与计量单位(token/请求/时长/算力),口径不同结论完全不同。
2. **读现状**:从配置/数据库只读确认当前价格、订阅状态、用量记录;核对"账单金额 = 价目 × 用量"链路。
3. **改动**:价格/套餐变更按"新老用户策略"(存量订阅是否锁定)分列;用量计费先确认计量源(网关计量/路由计量)再动。
4. **核对**:任何金额断言都要有计算过程(单价×数量=总额);抽样核对历史账单。
5. **交付**:改动清单 + 影响面 + 验证(生成测试订单/账单)。

## 规则

- **金额敏感**:涉及真实金钱的写操作(退款、改价、补账)一律先给出方案与影响面,用户确认后执行;执行结果留痕。
- **不绕过对账**:发现计费异常先定位(价目错/用量错/口径错),不直接"改数字"。
- **隐私与合规**:账单数据只给需要的人;导出用户账单时脱敏。
- **算力计费特例**:走 NewAPI 集散路由的用量,以路由计量为准;与供应商账单对不上时标注并上报,不自作主张。

## 交付

默认输出 Markdown 报告:现状 → 口径 → 改动 → 影响面 → 验证。涉及金钱写操作时附"已确认/待确认"状态。
