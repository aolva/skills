# Aolva RAG Ops

平台的检索增强链路:本地算力做 embedding(见 aolva-local-compute),生成走 ai-gateway
(见 aolva-llm-gateway)。本技能规范 RAG 系统的建设与运维,重点是**可评测、可溯源**。

## 架构约定

```
文档 → 解析(aolva-doc-qa) → 分块 → embedding(本地) → 向量库
查询 → 检索(top-k) → 组装上下文 → 生成(gateway) → 回答(带引用)
```

## 工作流

1. **需求澄清**:知识来源(文档/网站/代码)、更新频率、查询形态(问答/检索)、质量要求(引用粒度)。
2. **入库**:
   - 解析与清洗:去页眉页脚/水印,表格保结构;
   - 分块:按语义边界(章节/段落),块大小与重叠随文档类型定;块元数据(来源/页码/更新时间)必带;
   - 向量化:统一模型口径(embedding 模型/维度记录在案),批量入库断点续跑。
3. **检索增强**:
   - 查询改写:复杂问题拆子问题;
   - 检索:top-k 选择(默认 5),混合检索(关键词+向量)按需;
   - 组装:上下文带来源,回答强制引用块编号。
4. **评测(入库即测)**:
   - 指标:命中率(关键信息是否检索到)、引用正确率(回答引用的块是否真支持结论)、端到端准确率;
   - 测试集:每知识域 ≥20 条真实查询,入库/改库后回归。
5. **运维**:更新走增量(变更检测 → 重解析受影响块);失效块清理;查询日志用于持续评测。

## 规则

- **引用必带**:生成回答必须给来源(块编号 → 原文页码/URL),无引用不答或明说"未找到"。
- **口径一致**:embedding 模型变更 = 全库重向量化,新旧向量不混用。
- **权限**:含敏感知识的库,检索层做权限过滤;回答不泄露库外信息。
- **不糊回答**:检索结果不足时,明示"知识库中未覆盖",禁止让模型自由发挥。

## 交付

入库报告(块数/来源覆盖/评测基线)、评测集与结果、运维说明(增量更新命令)。
