# Aolva API Test

面向 HTTP API 的测试方法论:契约驱动,用例成体系,结果可复现。适配 REST/OpenAPI。

## 工作流

1. **拿契约**:优先 OpenAPI 文档/接口定义文件;没有则从代码路由/已有调用反推,并标注"非官方契约"。
2. **契约核对**:方法、路径、参数(必填/类型/枚举/校验规则)、鉴权方式、错误响应结构;发现契约自相矛盾先问用户。
3. **用例设计**(每个接口至少覆盖):
   - 正常路径:最小合法请求、带全参数请求;
   - 参数边界:必填缺失、类型错误、越界值、超长、枚举外值、特殊字符/注入载荷(只验证处理,不实际攻击);
   - 鉴权:无凭证、无效凭证、越权(用户 A 访问用户 B 资源);
   - 幂等与并发:重复提交、并发同资源;
   - 错误:4xx/5xx 响应体结构与文档一致。
4. **执行**:curl 或 python(urllib)脚本化;记录请求-响应(含状态码/耗时);失败即定位是"实现 bug"还是"契约问题"。
5. **报告**:用例矩阵(通过/失败/阻塞)、失败详情、风险点清单。

## 规则

- **只测可安全执行的操作**:对产生副作用(下单/删除/扣费)的接口,先确认是否允许真执行;不允许则用 sandbox 或只做契约级校验。
- **不泄漏凭证**:测试用的 token 走环境变量;报告里打码。
- **幂等验证**要有依据:接口声明幂等才断言重复提交安全。
- **超时与重试**:统一超时(默认 10s);网络抖动导致的失败单独标注,不混入功能失败。
- **可复现**:用例脚本 + 环境说明(基础 URL/鉴权方式)交付,他人可重跑。

## 交付

`api-tests/` 目录:用例脚本(可执行)+ `report.md`(用例矩阵与结论)。需要自动化回归时,建议封装为仓库 CI 步骤并说明改动点。
