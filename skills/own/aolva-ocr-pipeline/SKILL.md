# Aolva OCR Pipeline

Nurbell 产品线的核心是 document-intelligence(识别 → 抽取 → 结构化)。
本技能定义 OCR/文档智能任务的统一流程与质量门槛。

## 能力分层

| 层 | 能力 | 说明 |
|---|---|---|
| L1 | 文本识别 | 扫描件 → 文本(版面/行列保持) |
| L2 | 字段抽取 | 从识别结果抽取结构化字段(金额/日期/编号/名称) |
| L3 | 业务结构化 | 按业务模板(发票/合同/报表)映射到 schema |

按任务目标选层,不无脑走全链路(识别 + 抽取一次交付)。

## 工作流

1. **定目标与模板**:确认文档类型与目标 schema(字段清单、类型、必填/可选);没有现成模板时先让用户确认字段。
2. **预处理**:分辨率/方向/噪点检查;多页文档按页索引,不合并页码。
3. **识别**:优先走 Nurbell 文档智能服务;本地兜底(见 aolva-local-compute)时明确标注引擎与置信度口径。
4. **抽取**:字段值原样保留(大小写/单位/符号),格式错误(日期/金额)标注不静默修正。
5. **验证**:抽查关键字段(金额/编号等)与原文比对;置信度低或歧义的字段标记"待人工确认"。
6. **交付**:结构化结果(JSON/表格)+ 每字段出处(页码/坐标)+ 质量报告(识别率/抽全率)。

## 质量规则

- **出处必标**:每个抽取字段附页码定位;无法定位的字段标"推断"。
- **数字零容忍**:金额/日期逐字符核对;千分位、货币符号、小数点精度不丢。
- **不脑补**:识别不清的字/缺页/印章遮挡 → 标"低置信",禁止根据上下文猜值填入。
- **敏感信息**:证件号/手机号/账号按用户指示处理(默认脱敏),识别结果不扩散。
- **批量**:分批 + 失败重试有限次 + 断点续跑;进度可查。

## 交付

`ocr/<任务名>/`:原始输出、结构化结果、质量报告、抽检证据(原文截图+结果对照)。
